# Automatic AI work

`finance-autopilot` is an authenticated orchestration service, separate from the existing receipt, email and module inference services. It plans deterministic work from owner-scoped records, leases one task at a time across tabs, and checkpoints request IDs and outcomes in `finance_autopilot_work`. Email bodies and login tokens are never stored in its work journal. Existing receipt extraction and classification services retain their own encrypted inputs and strict evidence/financial protections.

Starting automatic work is an explicit one-time configuration action. It enables receipts and categories, plus timing and close prep for visible modules, preserving other task/source choices. Existing request allowance remains the only application-level budget: every analysis and research stage goes through the shared atomic reservation function. Provider billing limits apply independently; no separate monetary-cap promise is made. Provider/model changes pause for renewed configuration. Failed paid work opens a circuit and requires an explicit retry; saved successful inference is recovered under its original ID. Database leases serialize tabs. Closing a period is never automatic.

The planner processes receipts first, reuses stored receipt evidence for new bank imports without paying again, considers potential timing work without treating amount alone as evidence, categorizes batches of twenty in the oldest open quarter, and prepares that quarter for close. Already-enabled AI modules can get setup proposals when their configuration is absent. Manual modules stay manual. Questions block related purchases while independent work can continue. A saved answer is picked up automatically on the next pass. Confirmed, closed, offset, allocated/duplicate, movement and partner-owned records remain protected by shared eligibility checks and existing save RPCs.

The foreground provider runs only while a signed-in AI workspace is visible and online. It polls slowly when idle or capped. It is not an always-on cloud job. Gmail automatic-sync preference is respected, and initial mailbox connection remains a user action. Inventories are bounded to 5,000 rows per collection; larger histories stop for narrower review rather than claim completeness. Assistant close analysis remains bounded evidence, not certification of reconciled reports.

Saved ambiguous receipt results appear in the receipt workflow and can be used manually without another AI call. No raw email body is persisted there by this module. Leaving a failed task for manual review preserves its audit entry and its financial records.

Validation: pure planner tests, mocked end-to-end service execution with zero real paid calls, existing receipt/AI/module regressions, and rolled-back live SQL tests for owner isolation, grants, stale revisions, provider consent, cross-tab leases and unchanged ledger facts.
